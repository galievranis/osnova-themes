# Osnova HTML Playground

Работаем напрямую с исходным HTML, извлечённым из MHTML. Не пересоздавать интерфейс на Vue/React, не заменять исходные классы, сетку, стили и контент самодельными компонентами.

- Активные страницы: index.html (desktop), public/desktop.html и public/mobile.html.
- Исходные CSS, изображения и шрифты: public/original/.
- Оригинальные MHTML сохранять без изменений. scripts/restore_html.py восстанавливает HTML и перезаписывает рабочие страницы — не запускать поверх гипотез без сохранения изменений.
- SKILL.md — справочник и SVG; при расхождении визуальной геометрии ориентироваться на сохранённую разметку и CSS.
- Шапка 60 px, рекламный блок отдельно 42 px. Сохранять исходную реализацию.
- Гипотезы делать копиями HTML и небольшими локальными изменениями. Не подключать production JS/API.
- Проверять desktop и mobile в браузере, отсутствие ошибок загрузки локальных CSS и SVG. npm run build.

- Все навигационные ссылки только локальные. Не добавлять переходы на production. Для отсутствующих экранов использовать local.html; при восстановлении вызывать localize_links.localize.

- Адаптивность только через CSS, без перенаправлений или перезагрузки на resize. Все три HTML используют общую разметку, сборка через scripts/make_responsive.py. Проверять сужение и расширение в той же вкладке.

- На главной оставлять 10 постов. Для отсутствующих изображений использовать локальные public/placeholders/, не внешние URL. Обработка через scripts/prepare_feed.py и public/image-fallback.js.

- Все названия вкладок (<title>) начинаются с [PD], затем содержательное название экрана. Пример: [PD] Популярное — vc.ru. Не использовать общие названия вроде «прототип» вместо названия экрана. Сохранять правило при восстановлении HTML и создании гипотез.

- Блок скрытых/просмотренных постов (.feed-page__seen-posts-count) разрешён только в «Популярном». В «Свежем», рейтинге и других лентах его не показывать.

## Общие элементы и исключения для гипотез

- Одинаковые элементы в разных лентах по умолчанию используют общую исходную разметку, классы, размеры, отступы и адаптивное поведение. Не создавать визуальные различия из-за копирования страницы или изменения её содержимого.
- Сортировка ленты: на desktop текстовый контрол стоит на месте исходной даты; на mobile (до 924 px включительно) используется общая кнопка с иконкой сортировки. Набор пунктов меню может отличаться по лентам: например, «Новое / Всё» в «Свежем». Изменение пунктов меню само по себе не меняет вид кнопки.
- Это поведение по умолчанию можно переопределить явным требованием пользователя или конкретной гипотезы. Исключение реализовывать только на нужном экране через отдельный класс/стиль, не меняя общие элементы остальных страниц. В описании гипотезы фиксировать, что именно и зачем переопределено.

- Плейсхолдеры — настоящие фотографии, сохранённые локально: портреты для аватарок и фотографии для постов. Не использовать заглушки с размерами, надписью Image или другим служебным текстом.
- Проверять изображения по всей ленте, включая пустые оболочки видео из MHTML. Для отсутствующего видео показывать локальную фотографию. Фото в медиа и аватарках кадрировать через object-fit: cover без растягивания; сохранять исходный формат контейнера. Для разных постов выбирать разные фотографии. Проверять загрузку, видимость и заполнение кадра на mobile/tablet/desktop.
