# [PD] Osnova Tokens · 0.6.1

Локальное расширение Chrome для `https://themes-gta.dtf.osnova.app/`. Читает существующие CSS-переменные и меняет их значения в браузере. Серверные темы и настройки аккаунта не редактирует.

## Установка и обновление

1. В `chrome://extensions/` включите Developer mode.
2. Нажмите Load unpacked и выберите `extension/osnova-tokens`.
3. Обновите страницу стейджа и откройте Osnova Tokens на панели Chrome.

После изменения файлов нажмите Reload у расширения, обновите стейдж и откройте панель снова. Правки сохраняются между обновлениями. Перед удалением расширения экспортируйте CSS: удаление очищает его локальное хранилище.

## Темы

Для правки GTA выберите «Тема сайта» в панели и GTA в «Оформлении» сайта. Переключайте светлую и тёмную схемы кнопками панели. Изменяйте токены через поиск или инспектор. Текстовые значения сохраняются по Enter или после выхода из поля.

Для новой темы нажмите ＋ и задайте имя. Она всегда начинается с чистых исходных палитр «Классики» стейджа, независимо от выбранной темы и сохранённых правок базовой темы. Ничего сбрасывать перед созданием не нужно. Собственные темы можно выбирать и переименовывать. Пока своя тема активна, расширение удерживает её базовую тему после перезагрузок. Для переключения штатных тем сайта вернитесь к «Тема сайта».

Схемы сохраняются отдельно по стейджу, теме и режиму. «Вкл.» временно отключает применение, сохраняя правки. Стрелка у токена сбрасывает его; «Сбросить обе схемы» очищает обе палитры текущей темы.

## Только CSS для экспорта и импорта

В панели две кнопки: «Экспорт CSS» и «Импорт CSS». JSON больше не используется для файлов обмена. Внутреннее хранение расширения остаётся структурированным и не требует отдельного файла.

CSS содержит только изменённые токены обеих схем с исходными именами и селекторами `:root[data-theme="..."][data-color-mode="light|dark"]`. Подключайте его после CSS сайта. В начальном комментарии записаны стейдж, базовая тема и имя собственной темы; текстовые поля закодированы для безопасного хранения любых названий. Не удаляйте комментарий, если хотите сохранить имя темы при обратном импорте. Рисунки паттернов встроены в data URI и не требуют файлов расширения.

Чтобы продолжить работу, выберите соответствующую базовую тему и импортируйте CSS. Импорт заменяет изменения обеих схем, включая пустую схему. Именованный CSS создаёт отдельную собственную тему. Без имени импортируются правки текущей темы. CSS другого стейджа или базовой темы не принимается.

Поддерживается также прежний CSS-экспорт без служебного комментария: тема определяется по селекторам, имя не восстанавливается. Принимаются только блоки палитр с CSS-переменными. Обычные правила компонентов, внешние URL, @import, неизвестные токены и смешение нескольких тем отклоняются. Импортированный CSS не вставляется в страницу как произвольная таблица стилей: извлекаются только проверенные значения токенов.

## Инспектор

Нажмите «⌖ Инспектор», наведите на элемент и кликните. Клик выбирает элемент вместо обычного действия. Панель показывает переменные из подходящих CSS-правил элемента, его контрола, псевдоэлементов, ближайших фонов и наследуемого текста. Ссылки `var(...)` раскрываются до зависимых переменных. Крестик снимает фильтр; Escape отменяет выбор.

Правка токена применяется глобально к использующим его элементам. Локальные переменные, отсутствующие на корне, показаны без редактирования. Подходящие правила могут включать перекрытые каскадом декларации; это не полный анализ каскада DevTools.

## Редактор цвета

Нажатие на образец цвета открывает насыщенность/яркость, оттенок, прозрачность ползунком и полем «A, %», HEX и каналы RGB. Шахматная подложка показывает прозрачность. Изменения сразу видны на странице и сохраняются. «Готово» завершает редактирование; крестик и Escape возвращают значение до открытия.

Открытие без изменения сохраняет исходное значение или ссылку `var(...)`. RGBA точно хранит проценты, например 7% как `0.07`. HEX8 кодирует альфа-канал байтом и имеет соответствующее округление. Редактор рассчитан на sRGB. Сохранение проверяет исходную вкладку и тему.

## Паттерн

Доступны исходный рисунок, GTA, DTF, «Игры», отключение и загрузка SVG/PNG/JPEG/WebP до 1,5 МБ. Для растровой маски используйте прозрачный фон. SVG очищается от активных элементов и внешних ссылок. Один цвет или градиент, размер плитки и прозрачность хранятся в существующих токенах отдельно для схем.

## Покрытие и проверки

CSSOM читается из доступных таблиц, включая импорты и вложенные правила. Обе палитры снимаются без слоя правок через `getComputedStyle`, с восстановлением режима до отрисовки. Новые таблицы при переходах перечитываются; ↻ запускает пересканирование. Недоступные внешние CSS перечисляются в панели. Shadow DOM и отдельные фреймы не сканируются.

Проверки:

- `node extension/osnova-tokens/test.cjs`
- `node extension/osnova-tokens/color.test.cjs`
- `node extension/osnova-tokens/css-io.test.cjs`
- `npm run build`

В Chrome проверены установка, две схемы, сохранение, инспектор, паттерн, альфа-канал и отмена. В версии 0.3.1 выгружен CSS с текущими пользовательскими правками и импортирован обратно: сохранились 5 светлых и 2 тёмных изменения.

Документация API: https://developer.chrome.com/docs/extensions/reference/api/sidePanel и https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts.


## Цвет браузерной панели / Safari

В конце CSS-экспорта добавляется комментарий с двумя готовыми HTML-тегами `meta name="theme-color"` для светлой и тёмной схем. Цвет рассчитывается автоматически для небольшой области 5×3 пикселя у верхнего края по центру шапки. Учитываются `--theme-gradient-brand-header`, `--theme-color-brand-header`, порядок слоёв, прозрачность, фон страницы и размеры шапки (обычно 60 px по высоте). Для каждого режима используются сохранённые правки, даже если предпросмотр временно выключен. Поддерживаются linear-gradient и radial-gradient, в том числе несколько слоёв и repeating-варианты, с интерполяцией sRGB и premultiplied alpha. Неподдерживаемый синтаксис сообщает об ошибке вместо выгрузки заведомо неверного цвета. Без градиента используется заливка. Дополнительные CSS-токены не создаются.

Теги нужно перенести из комментария в `<head>` сайта. Один CSS-файл не задаёт HTML-метаданные браузеру автоматически. Атрибуты `media` следуют системной схеме; если приложение выбирает режим независимо, разработчику нужно обновлять `theme-color` при его переключении. Итоговый оттенок панели зависит от версии и настроек Safari; фактическое поведение Safari не проверялось. Экспорт проверен в Chrome: обе схемы и актуальные цвета попадают в файл; сохранённые пользовательские правки не меняются. Комментарий не мешает обратному CSS-импорту.

Источник: https://webkit.org/blog/11989/new-webkit-features-in-safari-15/.


`node extension/osnova-tokens/header-color.test.cjs` проверяет верхний край вместо середины по высоте, направления линейных градиентов, слои, прозрачность, радиальные эллипсы и размеры. Расчёт основан на CSS Images Level 3: https://www.w3.org/TR/css-images-3/. На текущей GTA при проверке получены светлый `#FCBDE0` и тёмный `#592972`; они включены в скачанный CSS. Сохранённые правки и режим страницы при экспорте не меняются.


## Цвета теней · 0.4.1

Нажмите образец у токена `--theme-shadow-*`. Для каждого существующего слоя доступен только цвет с прозрачностью через общий редактор цвета. Добавления, удаления, перестановки слоёв и контролов смещения, размытия, расширения и inset нет. Общее поле тени в списке доступно для чтения и копирования.

Сохранение заменяет исключительно цветовую часть выбранного слоя. Геометрия, порядок и число слоёв, inset, исходные числовые записи и пробелы сохраняются. Ссылки `var(...)` в нетронутых цветах тоже сохраняются. Если весь токен ссылается на составную тень, для цветовой правки используется её раскрытая запись с той же геометрией. Новые CSS-токены не создаются.

Изменения видны на странице и сохраняются в CSS-экспорт. «Готово» завершает редактирование, крестик и Escape возвращают значение до открытия. Отмена внутри редактора цвета возвращает только цвет текущего слоя. Открытие без правок не переписывает исходное значение.

`node extension/osnova-tokens/shadow.test.cjs` проверяет, что меняются только цвета, а геометрия, inset, порядок и количество слоёв, ссылки, числовая запись и пробелы остаются неизменными.


## Версии CSS-экспорта · 0.4.2

Имена экспортов имеют вид `osnova-gta-v001.css`, `osnova-gta-v002.css` и т. д. Счётчик хранится локально отдельно для стейджа и каждой базовой/собственной темы. Переименование собственной темы меняет часть имени файла, сохраняя счётчик; новая собственная тема начинает с v001. После v999 нумерация продолжается как v1000. В служебном комментарии CSS записывается `export-revision`.

Номер резервируется при экспорте, а не при изменении токена. Перезапуск браузера и обновление расширения не сбрасывают счётчик. Параллельные экспорты из разных окон получают разные последовательные номера. При отмене загрузки в браузере номер может быть пропущен. Удаление расширения очищает и счётчики. Импорт CSS не откатывает счётчик текущей темы.

Проверка: `node extension/osnova-tokens/export-version.test.cjs` — последовательность, разные темы, переименование, параллельные вызовы, перезапуск обработчика и безопасные имена файлов. В Chrome скачаны v001 и v002 текущей GTA; версия внутри каждого CSS совпала с именем, пользовательские правки не изменились.


## Исправление переключателя градиента · 0.4.3

При выключении градиента сохраняются второй цвет и полная предыдущая запись градиента (угол, цветовые точки и дополнительные слои). Включение восстанавливает её. Состояние переключателя хранится отдельно от значений цветов, поэтому даже одинаковые цвета не мешают включить градиент. Правки цветов при выключенном градиенте используются при последующем включении. Память разделена по теме и схеме, переживает перезагрузку и очищается при сбросе или импорте палитры. Это метаданные редактора, дополнительные CSS-токены не создаются. В CSS-экспорте остаётся только фактически выбранная заливка.

Если одноцветная заливка сохранена старой версией и второй цвет уже потерян, он подбирается из исходной палитры как стартовое значение. Самостоятельное изменение токена вне контролов паттерна сбрасывает устаревшие подсказки.

`node extension/osnova-tokens/pattern-state.test.cjs` проверяет повторные циклы off/on, восстановление исходной записи, сохранение второго цвета, правки при отключённом градиенте, одинаковые цвета и восстановление после старого дефекта. Основные проверки также покрывают сохранение настроек паттерна после перезагрузки и очистку при сбросе.


## Сохранённые «Игры» и DTF · 0.5.1

В список собственных тем автоматически добавляются «Игры» и DTF с обеими схемами, формулами состояний из существующего «Оформления» и соответствующими SVG-паттернами. Основа обеих — classic. Палитры собираются из `showcase/appearance-themes.json` через `scripts/showcase_catalog.py`; команда обновления пакета: `python3 scripts/package_extension_presets.py`. Сборка пресетов не меняет файлы витрины.

Серые примитивы локальной витрины заменены значениями, параметры backdrop-паттерна сопоставлены существующим токенам стейджа. Применяются и экспортируются только токены, имеющиеся на корневом элементе сайта. Новый ripple, которого нет в сохранённом каталоге, наследуется от текущей «Классики». Никаких дополнительных CSS-токенов в страницу не вводится.

Темы устанавливаются однократно под постоянными ID `preset-games` и `preset-dtf`. Повторный запуск не создаёт дубликатов, не перезаписывает правки и переименования пользователя, не сбрасывает активную тему или счётчик экспортов. Встроенные ресурсы упаковываются в data URI при экспорте.

Новые темы по ＋ теперь всегда создаются с пустыми правками на основе актуальной «Классики» сайта. Существующая тема с именем «Моя тема» переведена на classic с сохранением её сохранённых изменений. База именованных импортов определяется CSS-файлом.

Проверки: `node extension/osnova-tokens/presets.test.cjs` — исходные значения, схемы, паттерны, повторная установка и сохранность пользовательских данных. В Chrome проверены обе темы в двух режимах и паттерны. Скачаны `osnova-Игры-v001.css` и `osnova-DTF-v001.css`, обе схемы и SVG внутри файлов, обратный CSS-импорт разбирается корректно. У «Моей темы» подтверждены classic и исходная светлая шапка `#D9F0FF`.


## DTF = «Классика» + фон и паттерн · 0.5.2

У DTF остаются только `--theme-color-background`, `--theme-gradient-pattern`, `--theme-image-pattern`, `--theme-opacity-pattern`, `--theme-size-pattern` в каждой схеме. Текст, шапка, акценты, кнопки, состояния, тени и остальные токены наследуются напрямую от актуальной «Классики» стейджа. Формулы дополнительных оттенков для DTF не переопределяются.

Предыдущая DTF однократно обновляется до этой палитры (presetRevision 2), удаляя лишние переопределения. Пользовательские темы, «Игры» и счётчики экспортов не затрагиваются. Дальнейшие запуски не перезаписывают новые пользовательские правки.

В Chrome проверено: ровно 5 изменённых токенов в светлой и 5 в тёмной схеме; экспорт `osnova-DTF-v002.css` содержит только фон и паттерн. Для передачи разработчику используйте v002 вместо прежней v001.


## «Игры» = «Классика» + шапка, фон, паттерн и акцент · 0.5.3

Для «Игр» сохранены только `--theme-color-brand-header`, `--theme-gradient-brand-header`, `--theme-color-background`, `--theme-color-accent` и четыре токена паттерна (`gradient`, `image`, `opacity`, `size`). Ровно 8 переопределений в каждой схеме. Текст, острова, кнопки, состояния, тени, статусные цвета и остальные токены наследуются от актуальной «Классики». Связанные состояния акцента отдельно не пересчитываются.

Предыдущая палитра «Игр» обновляется однократно до presetRevision 2. DTF, пользовательские темы и счётчики экспортов не меняются. Проверено в Chrome и в выгруженном `osnova-Игры-v002.css`: в обеих схемах ровно разрешённые 8 токенов. Используйте v002 вместо прежней v001.


## Тёмные «Игры» и проверка контраста · 0.6.0

Тёмная палитра «Игр» согласована с фиолетовым фоном и лаймовым акцентом. Острова получают 8% белого поверх фона; вторичный и третичный текст — 80% и 70% основного текста на острове. Состояния акцента и мягкие заливки используют общие формулы. Статусные цвета и тени остаются из «Классики». Миграция presetRevision 3 обновляет только тёмную схему; светлая схема и её сохранённые правки остаются без изменений.

Внизу панели доступен сворачиваемый раздел «Контраст». Кнопка проверяет текущую палитру по вычисленным браузером цветам: текст от 4,5:1, значимые индикаторы, границы полей и фокус от 3:1. Для шапки проверяется сетка точек градиента. Это проверка заданных пар токенов, а не полный аудит всех страниц и изображений.

На стейдже тёмные «Игры» прошли 36 проверок без нарушений: минимальный проверенный текст 4,60:1, граница поля в hover 3,32:1; визуально проверены выбранное и невыбранное радио и активная навигация. Экспорт `osnova-Игры-v003.css` содержит 8 светлых и 81 тёмное переопределение. Используйте его вместо v002 для новой тёмной палитры.


## Готовые HEX/RGBA и правки пользователя · 0.6.1

Палитра «Игры» взята из пользовательского `osnova-Игры-v004.css`: ручные значения кнопок, hover/pressed и выбранного пункта меню сохранены. Все `color-mix()` вычислены в sRGB с учётом прозрачности без округления промежуточных цветов; итоговые каналы округлены до 8 бит. Цветовые ссылки и ссылки внутри градиентов заменены значениями. В CSS v005 нет `color-mix()`. Исходный v004 не изменяется.

Источник расширения — `showcase/games-extension-palette.json`. Новая миграция (revision 4) обновляет тёмную палитру на основе v004; последующие запуски сохраняют пользовательские правки. Светлая схема остаётся прежней. Файл v005 доступен в `exports/` для импорта и передачи разработчику. В Chrome повторены 36 проверок после конвертации: 34 прошли; на пользовательском minimal-pressed вторичный текст имеет 4,20:1, третичный — 3,37:1. Эти ручные цвета сохранены, а не исправлены автоматически.
